kith OS installer

Answer once. It installs without asking.

The installer asks at the machine's console: which disk, what name, what address, which cluster. Answer here instead, and this page writes kith-install.yaml for the stick. The machine then asks nothing.

The file is made in this page, in your browser. Nothing you type is sent anywhere or kept.

01 The stick

Start with a USB stick.

Write the installer to it: dd if=kith-os-installer.raw of=/dev/sdX. sh os/build.sh makes the file. Everything on that stick is lost. The answers go on it as one more file, at "Writing" below.

Several machines, no stick?

A node can install the machines beside it from the network (PXE), and hand each the installer once. The node's own web UI does that in its Install part (the Install link in the bar, at #/install): netboot on and off, with the cards to answer. A join token and netboot on or off are for who is bound to a Role that may apply Nodes, Roles and RoleBindings (anyone else gets a 403, and the page says so up front); the new recovery key, and the token, are answered with Cache-Control: no-store. From a terminal it is kith node netboot, which the guide describes.

05 The cluster

Alone, or beside others?

A node that starts a cluster offers a claim on its console. A node that joins needs the address of one of the cluster's nodes and a token that node made.

This node

kith node token on that cluster makes one. It goes into the file: keep the file as you would keep the token.

06 Encryption

Is its state locked?

Leave it off and the node is as every kith OS node is. The cluster can change most of what follows later.

With this on, the installer shows a recovery key once, on the machine's console, and then powers off. Be at the console, or watching it, and write the key down: it is the last stop on this page.

07 What it accepts

And what it refuses.

Leave it as it is and the cluster may have this node do anything.

The node takes kith OS releases signed by this key only. One to eight keys of 64 hex digits, with commas between. Rolling a release.

What the cluster may have this node do as its root
Which words

hardened turns every one off, so no NodeWorkloads (DaemonSets) run: hardened,host-users keeps them. no-KEY turns one off, and KEY turns it on again. devices=gpu+input names the classes of device a claim may hand out (devices=all, or devices= for none).

The keys: exec-units, root-containers, unconfined, node-network, vms, vm-paths, passthrough, host-paths, run, wipe. The classes: gpu, display, input, audio, usb, camera, other. What a node refuses.

08 Writing

Put it where the installer looks.

Nothing is asked or confirmed after this: a stick with answers erases the disk they name in whatever machine it starts. Start only machines you mean to erase.

The file names the disk it erases, and holds the join token and the release key. Keep the stick, and the file, private.

disk: "serial:S4EWNX0R123456"
hostname: alpha
ip: 10.0.0.5/24,10.0.0.1
dns: 10.0.0.1
join:
  address: 10.0.0.7:7443
  token: "3f9a1c7e5b2d4a60.alpha"
encrypt: true
releaseKey: "0f1e2d3c4b5a69788796a5b4c3d2e1f00f1e2d3c4b5a69788796a5b4c3d2e1f0"
lanReleases: true
nodePolicy: hardened

disk: nvme0n1
hostname: beta
ip: 10.0.0.6/24,10.0.0.1
join:
  address: 10.0.0.7:7443
  token: "3f9a1c7e5b2d4a60.beta"
nodePolicy: "hardened,vms,devices=gpu+input"

09 The recovery key

Write it down when it appears.

Only if you turned encryption on. Before it powers off, the installer prints the node's recovery key once, on the machine's console: 32 digits in groups of four. Be there, or watch the console, and write it down. It is shown that once, and kept nowhere you can read it later.

Typed at a waiting machine's console, the key opens the node's state where no cluster answers. An install nobody watched has a key nobody saw: kith node recovery NODE makes a new one, shown once.
